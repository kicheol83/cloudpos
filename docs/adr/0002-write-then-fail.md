# 0002. 실패를 기록하는 트랜잭션 메서드는 예외를 던지지 않는다

## 배경

PIN 실패 횟수를 올린 뒤 예외를 던지면 `@Transactional`이 롤백되어 카운트가 사라지고, 잠금이 동작하지 않았다. 리프레시 토큰 재사용 감지 후 토큰 패밀리를 폐기하는 부분에서도 같은 문제가 있었다. 둘 다 테스트에서 발견했다.

## 결정

- 실패를 저장해야 하는 서비스 메서드는 결과 타입(`PinVerification`, `RotationOutcome`)을 반환하고 정상 커밋한다.
- 예외는 트랜잭션 밖의 호출자가 던진다.
- 테스트는 실패 응답뿐 아니라 기록이 남았는지도 확인한다.

## 대안

`REQUIRES_NEW`는 커넥션을 하나 더 잡기 때문에 기본 방식으로 쓰지 않는다.
